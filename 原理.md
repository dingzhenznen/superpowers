  关键区别：

  1. 职责分离 - Implementer 负责"写"，Reviewer 负责"审"
  2. 审查顺序 - Code Quality Reviewer 只能在规范合规审查通过后调用（第7行）
  3. 专业化 - Code Reviewer 使用专门的模板
  requesting-code-review/code-reviewer.md，并额外关注文件职责划分、单元分解、文件大小等问题
  4. 工作流位置 - Implementer 是执行阶段，Reviewer 是验证阶段

⏺ 根据文件内容来看，Task tool (superpowers:code-reviewer) 不会创建 Agent。

  让我解释一下：

  Task tool (superpowers:code-reviewer):
    Use template at requesting-code-review/code-reviewer.md

  这里的 Task tool 指的是 TaskCreate 工具，而不是 Agent 工具。

  区别：

  ┌──────────┬─────────────────────────────────┬───────────────────────────────────────┐
  │          │   Task tool (general-purpose)   │ Task tool (superpowers:code-reviewer) │
  ├──────────┼─────────────────────────────────┼───────────────────────────────────────┤
  │ 实际工具 │ Agent 工具                      │ TaskCreate 工具                       │
  ├──────────┼─────────────────────────────────┼───────────────────────────────────────┤
  │ 创建什么 │ 创建一个子 Agent 来执行实现     │ 创建一个任务项，供后续处理            │
  ├──────────┼─────────────────────────────────┼───────────────────────────────────────┤
  │ 工作方式 │ 子 Agent 独立运行，有完整上下文 │ 只是记录任务，需要后续调度            │
  └──────────┴─────────────────────────────────┴───────────────────────────────────────┘

  为什么这样设计？

  代码质量审查是一个独立的验证步骤，它：
  1. 使用 TaskCreate 创建一个审查任务
  2. 这个任务会引用模板 requesting-code-review/code-reviewer.md
  3. 后续由控制器（或另一个 Agent）来执行这个审查任务

  而 Implementer 需要立即启动一个子 Agent 来执行实现工作，所以直接使用 Agent 工具。

  简单记忆：
  - 需要立即执行的独立工作 → 用 Agent 工具
  - 需要记录并后续处理的验证步骤 → 用 TaskCreate 工具

⏺ 现在我理解了完整的流程。

  答案

  superpowers:code-reviewer Agent 是在使用时动态创建的，不是预先存在的。

  流程如下：

  1. 在 code-quality-reviewer-prompt.md 中：
  Task tool (superpowers:code-reviewer):
    Use template at requesting-code-review/code-reviewer.md

  这里的 Task tool 实际上是 Agent 工具（虽然写的是 Task tool，但括号里的 superpowers:code-reviewer 表示 Agent 类型）。

  2. 在 requesting-code-review/SKILL.md 中明确说明：
  ▎ "Dispatch superpowers:code-reviewer subagent"

  ▎ "[Dispatch superpowers:code-reviewer subagent]"

  3. 实际调用时：
  Agent:
    subagent_type: superpowers:code-reviewer  # 指定 Agent 类型
    description: "Code review for..."
    prompt: |
      WHAT_WAS_IMPLEMENTED: ...
      PLAN_OR_REQUIREMENTS: ...
      BASE_SHA: ...
      HEAD_SHA: ...
      DESCRIPTION: ...

  关键点：

  ┌───────────────────────────┬───────────────────────────────────────────────────────────────────────┐
  │           问题            │                                 答案                                  │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────┤
  │ Agent 何时创建？          │ 当你调用 Agent 工具并指定 subagent_type: superpowers:code-reviewer 时 │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────┤
  │ 是预先存在的吗？          │ 不是，每次需要审查时动态创建                                          │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────┤
  │ code-reviewer.md 是什么？ │ 是 prompt 模板，告诉 Agent 如何执行代码审查                           │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────┤
  │ 为什么叫 "Task tool"？    │ 这是文档中的简化写法，实际对应的是 Agent 工具                         │
  └───────────────────────────┴───────────────────────────────────────────────────────────────────────┘

  所以完整的调用应该是使用 Agent 工具，指定 subagent_type: superpowers:code-reviewer，并填充 code-reviewer.md 模板中的变量。
